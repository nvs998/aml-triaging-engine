AML Sentinel

Payment screening that never blocks the gateway, run by a three-agent AI compliance crew that explains every verdict.

An asynchronous anti-money-laundering triage engine for UK payments. It validates ISO 20022 pacs.008 credit transfers, hands them to Sifter, OSINT and Risk Scorer agents in the background, checks beneficial owners against Companies House, and streams each step and the final verdict to a live dashboard.

01 / Overview

Accept in milliseconds. Investigate in the background. Explain every decision.

Agent loops take seconds, but a payment gateway can't wait. AML Sentinel splits the two: the API validates the message and returns 202 Accepted straight away, and the agents work on the case out of band, writing a plain-English rationale to an audit ledger.

ISO 20022 validation

Pydantic v2 models for debtor, creditor and transaction. Sort codes in any UK format are normalised to XX-XX-XX, and account numbers must be exactly 8 digits.

Non-blocking gateway

Each transfer is recorded as PROCESSING and given a TX-…-LON ID. Triage then runs as a FastAPI background task, and the client polls or listens for the result.

Three-agent CrewAI crew

A Sifter studies the debtor's payment history, an OSINT Investigator traces the creditor's ownership, and a Senior Compliance Officer agent combines their findings into a verdict.

Companies House UBO checks

Live lookups of company profiles and persons with significant control. Dormant companies, offshore owners and newly incorporated entities are flagged. A built-in mock registry keeps demos repeatable.

Schema-pinned verdicts

The final output is validated against a RiskAssessment model: LOW, MEDIUM or HIGH, a confidence score, a reasoning field capped at about 80 words, and an action (ALLOW, ESCALATE_TO_MLRO or FREEZE_ACCOUNT).

Live compliance stream

Every agent step is pushed over /ws/compliance as an AGENT_STEP event, followed by TRIAGE_COMPLETE with the full ledger row, which drives the dashboard as it happens.

02 / How it works

One payment, end to end

Ingest

POST /api/v1/transaction receives a pacs.008 payload and Pydantic validates and normalises it.

Acknowledge

A PROCESSING row is written to SQLite and the client gets 202 with a status URL.

Sift

The Sifter pulls the debtor's last 50 payments and checks for structuring, unusual payment frequency, escalating amounts and first-time payees.

Investigate

The OSINT agent looks up the creditor on Companies House, or records them as a private individual.

Score

The Risk Scorer applies MLR 2017 rules and returns a structured verdict with its reasoning.

Record & broadcast

The ledger row becomes APPROVED, ESCALATED or FROZEN, and TRIAGE_COMPLETE is sent to every connected client.

03 / Architecture

A thin gateway, a background crew, one audit ledger

FastAPI handles validation and I/O. All the reasoning happens in run_agentic_triage_loop(), which chooses a pipeline based on the API keys that are configured. Both agent tools read from systems of record: the ledger and Companies House.

04 / The agent crew

Specialist agents with real tools and a fixed output contract

Each agent has one job, one or two tools and no delegation. The prompts are written like a compliance team's working instructions, and the final step must return a typed object instead of free text.

  • Transaction Sifting Agent: its backstory covers JMLSG guidance and the placement, layering and integration stages. The task lists seven patterns to check one by one (structuring, round-number avoidance, frequency, escalating amounts, new payee, reference quality, clean history) and asks for a stated confidence level.
  • OSINT Corporate Investigator: calls companies_house_lookup when the creditor has a company number. Otherwise it records the payee as a private individual.
  • Senior AML Compliance Officer: combines both reports using explicit MLR 2017 rules and returns RiskAssessment through CrewAI's output_pydantic.
  • Grounded tools: LedgerQueryTool summarises the amount range and average and counts near-threshold payments. CompaniesHouseTool converts real profile and PSC data into the internal record format.
  • Two model routes: CrewAI on gemini/gemini-2.5-flash, or the Anthropic SDK's messages.parse with adaptive thinking and the same Pydantic schema.
05 / Resilience

Always produces a verdict, and fails safe when it can't

A compliance engine that silently drops a payment is worse than a slow one. The orchestrator steps down through simpler pipelines, and if everything fails it sends the case to manual review rather than approving it.

  • Pipeline chosen by configured keys: with a Gemini key the full CrewAI crew runs. With only an Anthropic key, deterministic sifting and a Companies House lookup are followed by Claude scoring. With no keys, a pure rules engine runs, so the demo works without credentials.
  • Fallback on exceptions: any error in the main pipeline reruns the case through the rules engine.
  • Fails closed: if the rules engine also fails, the row is marked ERROR with HIGH risk and ESCALATE_TO_MLRO, and the reasoning says manual review is required.
  • Sync-to-async bridge: CrewAI task callbacks run in a worker thread, so each broadcast is scheduled back onto FastAPI's event loop with asyncio.run_coroutine_threadsafe.
  • Repeatable demos: test company numbers come from a mock registry first, and the live API is only called for other numbers (with the UK prefix removed).
06 / Detection rules

Four typologies, higher severity wins

The rules engine and the Risk Scorer's instructions use the same rules, drawn from the UK Money Laundering Regulations 2017. The checks run in order and later matches override earlier ones, so a dormant company receiving £9,500 is scored HIGH, not MEDIUM.

TypologyTrigger in codeVerdict
Structuring / smurfingAmount between £9,000 and £9,999MEDIUM · ESCALATE_TO_MLRO

07 / Engineering decisions

Choices that shape the system

Return 202 before any reasoning

Multi-agent loops take seconds. Separating acknowledgement from investigation keeps the payment API fast and puts the slow work where it can be retried.

Typed output for every verdict

Risk, action and reasoning are validated against Literal enums, so later code never has to parse free-form model text to decide on a freeze.

Explanation stored with the decision

Each ledger row keeps a plain-English rationale next to the score, because account-freeze decisions must be defensible to the Financial Ombudsman.

Works with zero credentials

The configured keys pick the pipeline, so anyone can clone the repo and get real verdicts and events without an API key.

Fail toward a human

When every pipeline fails, the system escalates to the MLRO with HIGH risk instead of approving the payment.

09 / FAQ

Questions, answered

What does AML Sentinel do?

It screens UK credit transfers (ISO 20022 pacs.008) for money-laundering red flags: structuring just below £10,000, dormant shell companies, offshore beneficial owners and high-value transfers. Each payment gets a risk score, a recommended action and a written rationale.

Is it production software?

No. It's a working prototype and portfolio project. It runs end to end and is deployed as a demo on Azure Container Apps, but it has no automated test suite, uses SQLite with a single replica, and includes no formal regulatory sign-off.

Which models does it use?

The full agent crew runs on Gemini 2.5 Flash through CrewAI. If only an Anthropic key is configured, a Claude model scores the risk through the Anthropic SDK's structured messages.parse. With no keys it uses a deterministic rules engine.

How do humans stay in control?

Medium-risk cases are escalated to the MLRO, and system failures default to manual review. A human approval step before any account freeze is the top item on the roadmap. Today, HIGH verdicts are recorded as FROZEN with a recommended action rather than run against a real bank.

Where does the company data come from?

From the official Companies House public API (company profile and persons with significant control) when an API key is set. Three test company numbers are served from a built-in mock registry, so every risk path can be demonstrated without a key.

Can I run it myself?

Yes. Clone the repo, install requirements.txt with uv and start uvicorn app.main:app. The dashboard is at / and the API docs at /docs. scripts/submit_transactions.py can generate and post realistic test payments. A multi-stage Dockerfile is included.
