AML Sentinel

Async AML triage run by an AI compliance crew

An anti-money-laundering triage engine for UK payments. It validates ISO 20022 pacs.008 credit transfers and accepts them instantly, then hands each one to AI agents working in the background. A Sifter studies the payer's history, an OSINT investigator traces the payee's real owners on Companies House, and a Risk Scorer applies MLR 2017 rules. Every verdict is streamed live and stored with a plain-English explanation.

01 / Overview

Helping compliance teams find the transactions that matter

The problem

Compliance teams in UK banks must spot the few suspicious payments hidden among thousands of legitimate ones, investigate each one, and prove afterwards why the money was allowed, escalated or frozen.

  • Laundering patterns are easy to miss by hand: payments split just under £10,000, dormant shell companies, owners hidden offshore.
  • Every flagged case means gathering evidence from several places, such as the payer's history and the Companies House record, which eats analyst time.
  • Regulators and the Financial Ombudsman expect a clear audit trail of where the money went and why each decision was made.
  • All of this has to happen without holding up legitimate payments.
How it solves it

AML Sentinel does the first investigation automatically. AI agents flag risky payments with a risk level and an action plan, and every finding is recorded so analysts start from a prepared case and the money trail can be audited later.

  1. Validate: the pacs.008 message, normalise UK sort codes and account numbers, and send back an acknowledgement with a tracking ID.
  2. Sift: the payer's last 50 payments for structuring, unusual frequency, escalating amounts and first-time payees.
  3. Investigate: the payee on Companies House: status, incorporation date and persons with significant control.
  4. Score: against MLR 2017 rules into LOW, MEDIUM or HIGH with an action plan: allow, escalate to the MLRO, or freeze.
  5. Stream and record: each agent step live over WebSocket, and store the verdict and rationale in the audit ledger.
02 / Architecture

A thin gateway, a background crew, one audit ledger

Payments are validated and acknowledged straight away. AI agents then investigate each one in the background, drawing on payment history, company records and an LLM, and every verdict is saved with its reasoning.

Core components

FastAPI gateway

Accepts ISO 20022 payloads, sends an acknowledgement straight away, and serves the status, ledger and WebSocket endpoints.

ISO 20022 parser

Pydantic v2 models for debtor, creditor and transaction, with validators for UK sort codes and account numbers.

Triage orchestrator

Chooses the CrewAI, Claude or rules pipeline, falls back on errors, and fails safe to manual review.

Agent crew

Sifter, OSINT Investigator and Risk Scorer run in sequence on CrewAI, ending in a schema-pinned RiskAssessment.

Agent tools

LedgerQueryTool reads payment history; CompaniesHouseTool fetches company profiles and beneficial owners.

Audit ledger

Async SQLite store of every transaction with its risk score, confidence, reasoning and recommended action.

Live dashboard

Streams AGENT_STEP and TRIAGE_COMPLETE events so each investigation can be watched as it happens.

03 / Business value

Where it helps a compliance team

Payments are never held up

Screening runs outside the request path, so customers get an instant acknowledgement while checks continue.

Decisions you can defend

Every verdict is stored with a plain-English rationale and a recommended action, giving an audit trail for regulators and complaints.

Cases arrive pre-investigated

Payment-history patterns and ownership findings are gathered before a compliance officer opens the case.

Works at any budget

Runs with Gemini, with Claude, or with no LLM at all, and sends failures to manual review instead of approving them.

04 / Key takeaways

What I learned building it

01

Keep slow AI off the request path

Returning 202 and investigating in the background keeps the API fast however long the agents take.

02

Pin model output to a schema

Typed enums for risk and action mean no code ever parses free text to decide on a freeze.

03

Ground agents with real tools

Giving agents ledger history and registry data lets them cite evidence instead of guessing from the payload alone.

04

Bridge sync frameworks and async servers

CrewAI callbacks run in worker threads, so every live event has to be scheduled safely back onto FastAPI's event loop.

05

Design for failure first

Layered fallbacks and a fail-safe default keep the system producing verdicts when a model or API is down.

06

Domain rules shape the prompts

Writing prompts as a compliance team's working instructions, citing MLR 2017 and JMLSG, gives each agent a clear checklist to follow.

06 / FAQ

Questions, answered

What does AML Sentinel do?

It screens UK credit transfers for money-laundering red flags (structuring under £10,000, dormant shell companies, offshore beneficial owners and high-value transfers) and gives each payment a risk score, a recommended action and a written rationale.

Is it production software?

No. It's a working prototype and portfolio project. It runs end to end and is deployed as a demo on Azure Container Apps, but it has no automated test suite, uses SQLite with a single replica, and has no formal regulatory sign-off.

Which models does it use?

The full agent crew runs on Gemini 2.5 Flash through CrewAI. With only an Anthropic key, a Claude model scores the risk using structured output. With no keys, a deterministic rules engine runs instead.

How do humans stay in control?

Medium-risk cases are escalated to the MLRO, and any system failure defaults to manual review. A human approval step before any freeze is the top item in the future scope.

Where does the company data come from?

From the official Companies House API (company profile and persons with significant control) when a key is set. Three test companies come from a built-in mock registry so every risk path can be demonstrated without one.

Can I run it myself?

Yes. Clone the repo, install requirements.txt with uv and start uvicorn app.main:app. The dashboard is at / and the API docs at /docs; scripts/submit_transactions.py generates realistic test payments.
